# 読み取りモードのモデル

`ReadMode.tla` は「誰がいつどの鍵の写しを持つか」を TLA+ で書いたもの(#22 の仕様、#24)。`ReadMode.cfg` が端末 2 台・文書 2 本・エージェント 1 つ・時刻 0〜3・版 0〜2 の範囲で TLC にかける。`Broken/` の各設定は、確かめる仕組みを一つずつ外したもので、TLC が失敗しなければならない。

```sh
scripts/model-check.sh
```

正しいモデルが通り、壊したものがそれぞれ決まった性質で落ちれば成功。一つの壊し方の反例を全部見るときは名前を渡す。

```sh
scripts/model-check.sh AcceptExpired
```

Java 11 以上が要る(`brew install openjdk`)。TLC 1.7.4 は初回に `~/.cache/mai/` へ落とし、SHA-256 を確かめる。

## 状態

サーバーは設定(モード・除外・取り消した鍵)と写しの正本を持つ。端末は最後に同期した設定 `view[d]` と自分の時計 `clock[d]` で動く。同期していない端末や時計の遅れた端末は、サーバーが断るべき写しを送ることがある。時計の遅れは、前に作った写しが遅れて届く場合も表す。

除外はサーバーが文書 ID ごとに知っている。除外の設定そのものは暗号化して同期し、サーバーには写しを作らない文書 ID だけが渡る(#22 で決めた)。

| 変数 | 意味 |
|---|---|
| `now` | サーバーの時刻 |
| `clock[d]` | 端末の時計。`now` より進むことはない |
| `version[w]` | 文書の版。保存のたびに文書の鍵を作り直す |
| `excluded[w]` | サーバーが持つ除外 |
| `mode` | サーバーが持つモード `[on, until]` |
| `postedKey[a]` | サーバーが配るエージェントの公開鍵。`NoKey` か、本人の鍵か、`ForgedKey` |
| `signed` | iPhone で承認して署名した公開鍵 |
| `revoked` | 登録を取り消した公開鍵 |
| `copies` | サーバーが持つエージェントあての写し `[writing, version, agent, key, expires]` |
| `wrappedFor` | 端末が一度でも文書の鍵を包んだ公開鍵(サーバーが受けたかどうかによらない) |
| `view[d]` | 端末が最後に同期した設定 |

## 操作

| 操作 | 内容 |
|---|---|
| `Save(d, w)` | 版を上げ、`view[d]` と `clock[d]` でモードがオンなら写しを作って送る。古い版の写しは消える |
| `TurnOn(d, until)` | モードをオンにし、`view[d]` で除外していない文書をすべて包んで送る。前の期間の写しは消える。サーバーの時刻で終わっている期間は断る |
| `TurnOff(d)` | モードをオフにし、写しをすべて消す |
| `Exclude(d, w)` / `Include(d, w)` | 除外する(写しをすぐ消す)/ 戻す(写しは次の保存で作る) |
| `Sync(d)` | 端末がサーバーの設定を取り込む |
| `PostKey(a)` / `PostForgedKey(a)` | エージェント本人の鍵 / 承認されていない鍵がサーバーに置かれる |
| `Approve(a)` | iPhone がエージェント本人から受け取った鍵に署名する |
| `Revoke(d, a)` | 登録を取り消し、その鍵あての写しを消す |
| `Tick` | サーバーの時刻が進む。期限が来たモードはオフになり、期限の来た写しは消える |
| `DeviceTick(d)` | 端末の時計が進む |

端末が包む前に確かめることは `KeyIsTrusted` と `DeviceWraps`、サーバーが写しを受ける前に確かめることは `ServerAccepts` にある。

## 性質

| 性質 | 内容 |
|---|---|
| `NoCopyOfExcluded` | 除外した文書には、エージェントあての写しが存在しない |
| `NoCopyPastExpiry` | 期限が過ぎたら、写しは残っていない |
| `NeverWrapForUnsignedKey` | 署名のない公開鍵には、文書の鍵を包まない |
| `NoCopyOutsideMode` | 写しはモードがオンの間だけあり、期限はそのモードの期限と同じ |
| `NoCopyForRevokedKey` | 取り消した鍵あての写しはない |
| `CopyIsOfCurrentVersion` | 写しは文書の今の版のものだけ |
| `ModeEndsOnTime` | モードがオンなのは期限の前だけ |
| `ClockNeverAhead` | 端末の時計はサーバーの時計より進まない |

上の 3 つが #24 の性質。次の 3 つは、オフ・取り消し・保存で写しが消えることを確かめる。最後の 2 つはモデルの前提が保たれていることを確かめる。`NoCopyPastExpiry` は `NoCopyOutsideMode` と `ModeEndsOnTime` から導かれるので、それを落とす壊し方は `NoCopyOutsideMode` も落とす。壊したモデルの設定は落ちるべき性質だけを確かめる。

写しを持つのはサーバーなので、性質はどれもサーバーの写しか端末が包んだ鍵について書いてある。端末が包む前に除外・期限・取り消しを確かめること(`DeviceWraps`、`KeyIsTrusted` の取り消し)は、外してもサーバーが断るので、どの性質も落ちない。写しが作られるべきときに作られること(漏れなく)も確かめていない。

## 反例(#26 のテストの例)

壊し方ごとに TLC が見つけた最短の手順(壊したモデルは 1 ワーカーの幅優先で探すので、最短になる)。端末は `d1`・`d2`、文書は `w1`・`w2`、エージェントは `a1`、`K` は `a1` 本人の鍵。どれも時刻 0、端末の時計も 0 から始まる。

### AcceptExcluded — サーバーが除外を確かめない → `NoCopyOfExcluded`

1. `d1` が `w1` を除外する。`d2` はまだ同期していない。
2. `a1` が `K` を置き、iPhone が `K` に署名する。
3. `d2` が期限 1 でモードをオンにする。`d2` には `w1` が除外に見えないので、`w1` と `w2` を `K` に包んで送る。
4. サーバーが `w1` の写しを受ける。除外した `w1` の写しがある。

正しいサーバーは 4 で `w1` の写しを断り、`w2` の写しだけを持つ。

### KeepCopyOnExclude — 除外しても写しを消さない → `NoCopyOfExcluded`

1. `a1` が `K` を置き、iPhone が署名する。
2. `d1` が期限 1 でモードをオンにする。`w1`・`w2` の写しができる。
3. `d1` が `w1` を除外する。`w1` の写しが残る。

### AcceptExpired — サーバーが期限とモードを確かめない → `NoCopyPastExpiry`

1. `d1` が期限 1 でモードをオンにする。
2. `a1` が `K` を置き、iPhone が署名する。
3. サーバーの時刻が 1 になり、モードはオフになる。`d1` の時計は 0 のまま。
4. `d1` が `w1` を保存する(版 1)。`d1` の時計ではまだ期限前なので、期限 1 の写しを送る。
5. サーバーが受ける。時刻 1 で期限 1 の写しがある。

正しいサーバーは 5 で断る。

### KeepExpiredCopy — 期限が来ても写しを消さない → `NoCopyPastExpiry`

1. `a1` が `K` を置き、iPhone が署名する。
2. `d1` が期限 1 でモードをオンにする。`w1`・`w2` の写しができる。
3. サーバーの時刻が 1 になる。モードはオフになるが、写しが残る。

### KeepCopyOnTurnOff — オフにしても写しを消さない → `NoCopyOutsideMode`

1. `a1` が `K` を置き、iPhone が署名する。
2. `d1` が期限 1 でモードをオンにする。`w1`・`w2` の写しができる。
3. `d1` がモードをオフにする。写しが残る。

### SkipSignatureCheck — 端末が署名を確かめない → `NeverWrapForUnsignedKey`

1. `a1` が `K` を置く。iPhone はまだ承認していない。
2. `d1` がモードをオンにし、署名のない `K` に `w1`・`w2` の鍵を包む。

承認されていない `ForgedKey` が置かれた場合も同じ手順で落ちる。

### AcceptRevoked — サーバーが取り消しを確かめない → `NoCopyForRevokedKey`

1. `a1` が `K` を置き、iPhone が署名する。
2. `d1` が `a1` の登録を取り消す。`d2` はまだ同期していない。
3. `d2` が期限 1 でモードをオンにする。`d2` には `K` が取り消しに見えないので、`w1`・`w2` を `K` に包んで送る。
4. サーバーが受ける。取り消した `K` あての写しがある。

### KeepOldVersionCopy — 保存しても古い版の写しを消さない → `CopyIsOfCurrentVersion`

1. `a1` が `K` を置き、iPhone が署名する。
2. `d1` が期限 1 でモードをオンにする。`w1`・`w2` の版 0 の写しができる。
3. `d1` が `w1` を保存する。版 1 の写しができ、版 0 の写しが残る。

## モデルにしていないこと

- 取り消した後の再登録(取り消しはその鍵について最後)。
- 暗号文を取ってくるトークン。写しがサーバーにあるかだけを見る。
- エージェントが一度受け取った写し。サーバーから消えても、エージェントが手元に残した鍵は消せない。
- オンの間に期間を延ばしたり縮めたりすること。オンにできるのは、その端末にモードがオフに見えるときだけ。
